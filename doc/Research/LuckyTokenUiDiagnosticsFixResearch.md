# Token UI and diagnostics defect research

Date: 2026-08-24

## Confirmed findings

- Public model aliases are owned by `normalizeModelName` and `allocateDefaultAlias`. The old slash-to-dash normalization did not implement the requested `<provider>/<last model-id segment>` contract. Source: [`src/public-models/authority.ts`](../../src/public-models/authority.ts).
- Public Model commands use optimistic revisions and return `conflict` with the current state. The Provider renderer previously accepted the conflict state but did not retry the user's mutation, so catalog reconciliation could make an edit appear to do nothing. Sources: [`src/public-models/authority.ts`](../../src/public-models/authority.ts), [`packages/desktop-shell/src/renderer/providers/ProvidersPage.tsx`](../../packages/desktop-shell/src/renderer/providers/ProvidersPage.tsx).
- Request summary records originally omitted the request-time model selector, session/profile facts, and final HTTP status even though those facts already existed in journey observations and indexed diagnostic columns. The Overview table therefore depended on lazily loaded detail and frequently rendered blanks. Sources: [`src/diagnostics/worker-program.ts`](../../src/diagnostics/worker-program.ts), [`packages/application-control-plane/src/request-diagnostics-contract.ts`](../../packages/application-control-plane/src/request-diagnostics-contract.ts), [`packages/desktop-shell/src/renderer/overview/OverviewPage.tsx`](../../packages/desktop-shell/src/renderer/overview/OverviewPage.tsx).
- Request Journey subscriptions publish closed journeys by contract, so they cannot be an authority for the current active-request count. The server already owns the exact HTTP and WebSocket request sets; their combined size is now published through application status without changing diagnostics lifecycle semantics. Sources: [`src/server.ts`](../../src/server.ts), [`src/application.ts`](../../src/application.ts), [`packages/application-control-plane/src/contracts.ts`](../../packages/application-control-plane/src/contracts.ts).
- A Profile is projected as `ready` after a successful credential usage record exists. The Provider runtime already accepted a `credentialUsage` source, but application composition did not supply one, so a Profile could continue to show `not_yet_verified` despite serving requests. Sources: [`src/credentials/profile-authority.ts`](../../src/credentials/profile-authority.ts), [`src/providers/runtime.ts`](../../src/providers/runtime.ts), [`src/application.ts`](../../src/application.ts).
- Electron supplies a standard application menu unless Main explicitly removes it. Product naming and installer executable naming are controlled separately in Forge, Electron Main, and renderer text. Sources: [`packages/desktop-shell/src/main/main.ts`](../../packages/desktop-shell/src/main/main.ts), [`packages/desktop-shell/forge.config.cjs`](../../packages/desktop-shell/forge.config.cjs).
- The old request-detail view mixed identifiers, optional captures, and failure fields into one flat presentation. In particular, a Provider ID could appear where a Profile was absent, and successful requests still received a failure-shaped section. The replacement separates confirmed request facts, a five-stage lifecycle, failure evidence, exact stored observations, and optional captures; absent evidence is reported as not recorded and is never inferred. Sources: [`packages/desktop-shell/src/renderer/overview/OverviewPage.tsx`](../../packages/desktop-shell/src/renderer/overview/OverviewPage.tsx), [`packages/desktop-shell/test/overview-requests.test.tsx`](../../packages/desktop-shell/test/overview-requests.test.tsx).

## CommandCode and MCP observations

- An authenticated first-party CommandCode model-catalog query returned 58 upstream model IDs. Every ID shared with the local catalog matched exactly; the Goat catalog intentionally exposed a smaller 40-model set. No evidence supported treating Goat model IDs as Private model IDs.
- Recent inspected Goat requests did not show an upstream model-ID rejection. The reported failing interaction was aborted after Codex reported `Mcp error: -32603` while invoking `codex_apps/code.glob`, which places the immediate failure at the client/MCP tool boundary rather than in the model request.
- MCP tool definitions must be model-visible for a model to choose a tool. In the Responses conversion lane, tool definitions travel in the request and tool calls/results remain part of the response/history conversion contract. The MCP server implementation, credentials, and transport are not model-visible. Sources: [`src/protocols/openai-responses`](../../src/protocols/openai-responses), [`doc/Spec/LuckyTokenOpenAIResponsesSemanticConversionArchitectureSpec.md`](../Spec/LuckyTokenOpenAIResponsesSemanticConversionArchitectureSpec.md).

No API keys, credential values, or user-owned Codex state are recorded in this note.
